# Деплой на GitHub Pages

## Автоматический деплой (рекомендуется)

Сайт автоматически деплоится на GitHub Pages при каждом пуше в ветку `main` или `master`.

### Настройка GitHub Pages (один раз)

1. Перейдите в Settings вашего репозитория на GitHub
2. В меню слева выберите **Pages**
3. В разделе **Source** выберите **GitHub Actions**
4. Сохраните изменения

После этого при каждом `git push` сайт будет автоматически обновляться.

### URL сайта

После деплоя сайт будет доступен по адресу:
```
https://dun4ev.com/
```

---

## Повторная публикация

Чтобы повторно опубликовать версию из удаленной ветки `main`, войдите в GitHub CLI (`gh auth login`) и выполните команду в каталоге репозитория.

```bash
npm run deploy
```

Команда запускает `deploy.yml` через GitHub Actions. Workflow берет исходники из GitHub, собирает сайт, проверяет SEO и передает сборку в Pages. Для публикации локальных изменений сначала отправьте нужные коммиты в `main`. Успешное завершение команды означает, что GitHub принял запрос. Результат публикации появляется во вкладке Actions.

---

## Проверка перед деплоем

Перед деплоем рекомендуется проверить production сборку локально:

```bash
npm run build
npm run preview
```

Откройте http://localhost:4173 и убедитесь, что всё работает корректно.

## Важные замечания

### ⚠️ API ключи

Переменные окружения (например, `GEMINI_API_KEY`) **не будут работать** на GitHub Pages, так как это статический хостинг.

**Решения:**
1. Удалить функционал, требующий API ключей
2. Создать отдельный backend для API запросов
3. Использовать другой хостинг (Vercel, Netlify), который поддерживает переменные окружения

### 📁 Структура путей

Все пути в проекте настроены с учётом base path `/`. Так как вы переименовываете репозиторий в `dun4ev.github.io`, параметр `base` в `vite.config.ts` теперь равен `/`.

### 🔄 Обновление сайта

Чтобы обновить сайт:
```bash
git add .
git commit -m "Update site"
git push
```

Результат сборки и публикации появится во вкладке Actions.
