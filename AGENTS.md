# AGENTS.md

Локальные правила для сайта-портфолио. Глобальные инструкции действуют полностью; этот файл содержит только проектные уточнения.

Актуально на 2026-07-28.

## Язык

- Отвечай на русском языке.
- Код и имена сущностей пиши на английском.
- Не меняй кириллицу и транслитерацию в пользовательских строках без явного запроса.
- Используй UTF-8.

## Проект

- Статический сайт-портфолио без серверной части.
- Стек: React 19, TypeScript 5.8, Vite 6, i18next, D3 и Recharts.
- Пакетный менеджер: npm.
- Деплой: GitHub Pages через `gh-pages`.
- Актуальные версии и команды всегда проверяй по `package.json`.

## Структура

- `App.tsx` и `index.tsx`: вход и корневой UI.
- `components/`: React-компоненты.
- `constants.ts`: данные проектов и общие константы.
- `types.ts`: общие TypeScript-типы.
- `src/locales/`: русская и английская локализации.
- `public/`: статические файлы и изображения.
- `docs/`: документация по сопровождению и деплою.

## Правила изменений

- Делай минимальные изменения в рамках запроса и сохраняй существующий визуальный стиль.
- Не рефактори соседний код без необходимости.
- Не перезаписывай незнакомые или незакоммиченные изменения пользователя.
- При изменении пользовательского текста синхронизируй `ru` и `en`, если запрос не ограничен одним языком.
- Локальные изображения размещай в `public/images/` и подключай с учетом `import.meta.env.BASE_URL`.
- Не добавляй зависимости, новые абстракции или файлы без практической необходимости.
- Не обновляй версию, `CHANGELOG.md`, `README.md` или `docs/ROADMAP.md` для обычной локальной правки, если пользователь не запросил релиз или изменение документации.
- Не создавай patch-файлы, ветки, коммиты, PR и не выполняй деплой без прямого запроса.
- `AGENTS.md` является единственным проектным источником инструкций для агентов. Не создавай дублирующий `GEMINI.md`.

## Проверка

- Для изменения кода используй минимальную релевантную проверку.
- Основная production-проверка: `npm run build`.
- Статическая проверка типов при необходимости: `npx tsc --noEmit`.
- Для правки текста, изображения или документации достаточно проверить измененные файлы и ссылки на ресурсы; сборку запускай, если изменение влияет на импорт, путь или рендеринг.
- Не утверждай, что проверка прошла, если она не запускалась.

## Команды

```bash
npm install
npm run dev
npm run build
npm run preview
npm run deploy
```

`npm run deploy` публикует сайт и требует явного запроса пользователя.

## Ответ пользователю

- Начинай с результата.
- Для выполненной правки кратко укажи измененные файлы и проведенную проверку.
- Не используй обязательные шаблоны, Patch Report или полный пошаговый отчет, если пользователь их не запросил.
- Упоминай риски, ограничения и непроведенные проверки только когда они существенны.
